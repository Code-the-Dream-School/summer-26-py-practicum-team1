# Team Working Agreement

## Purpose

This document describes how Team 1 will collaborate during the Code the Dream Python Practicum. It establishes shared expectations for communication, task management, code reviews, and learning throughout the project.

## Communication

- Slack is our primary communication channel.
- Please check Slack regularly and acknowledge messages that require a response in a timely manner.
- Share pull requests in Slack so everyone has a chance to review them.
- Keep communication respectful and constructive.

## Meetings

- The team meets every Wednesday at 6:30 PM ET.
- Daily stand-up reminders are posted in Slack at 8:00 PM ET.
- Stand-up updates should briefly cover:
  - What was completed
  - What will be worked on next
  - Any blockers

## Work Management

- All work is tracked in Jira.
- Large tasks should be broken down into smaller, focused work items whenever practical.
- Team members should keep their Jira issue status up to date.

## Blockers

- If you encounter a blocker, raise it in Slack as soon as possible.
- If a blocker requires additional work, a follow-up Jira issue should be created.
- Mentors should be involved early if a blocker may affect sprint progress.

## Pull Requests and Code Reviews

- Every code change should be made in a feature branch.
- Pull requests should reference the corresponding Jira issue whenever applicable.
- Pull requests should be posted in Slack for review.
- Team members should review pull requests promptly whenever possible.
- Authors should address review feedback before requesting final approval.

## Merge Requirements

A pull request is ready to be merged after:

- at least one mentor approval;
- at least two student approvals;
- all review feedback has been addressed.

## Roles and Learning

- Everyone is encouraged to participate in planning, implementation, testing, documentation, and code reviews.
- Team members should have opportunities to work on different parts of the project throughout the practicum.
- The team lead helps coordinate communication and sprint progress.
- Technical decisions are made collaboratively by the team.

## Learning and Knowledge Sharing

- Team members are encouraged to ask questions and share knowledge with each other.
- Code reviews should be used as learning opportunities, not only for finding issues.
- When possible, responsibilities should rotate so everyone gains experience across different parts of the project.

## Updating this Agreement

This agreement may be updated throughout the practicum if the team agrees that changes will improve collaboration or workflow.
